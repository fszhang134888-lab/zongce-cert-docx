## 1. 页面与段落（读自官方 docx 的 XML）

```
pgSz   11906 × 16838 twips = A4 595.3 × 841.9 pt
pgMar  top 1440 / bottom 1440 / left 1800 / right 1800 twips
       = 2.54cm / 2.54cm / 3.17cm / 3.17cm，版心 415.6pt
docGrid type=lines, linePitch=312 twips = 15.6pt/行
```

| 元素 | 字体字号 | 段落属性 |
|---|---|---|
| 标题（占位"标题"） | 宋体 22pt（sz=44） | heading 1，居中，段前 17pt / 段后 16.5pt，行距 auto |
| 正文 | 仿宋 16pt（sz=32） | Normal，左对齐，首行缩进 32pt / 2 字符，行距 auto |
| 特此证明。 | 仿宋 16pt | 同上 |
| 名单如下: | 仿宋 16pt | 同上（原始文件用的是半角冒号，正式件建议用全角「：」） |
| 日期 / 单位 | 仿宋 16pt | 右对齐，缩进 0 |

Normal 样式：`仿宋 / sz=32 / 左对齐 / widowControl=0`，未设 spacing → 单倍。
docDefaults 的 eastAsia 是宋体，但 Normal 明确写了仿宋，所以正文落仿宋。

## 2. 名单表格（官方 docx 的 tblPr）

```
tblW        8550 twips = 427.5pt（比版心 415.6 宽 11.9pt，实际会压出右边界）
tblpPr      浮动表：horzAnchor=page, tblpX=1779(89pt), vertAnchor=text, tblpY=103
tblBorders  六个方向全部 none
tblLayout   fixed
tblCellMar  left/right 108 twips = 5.4pt, top/bottom 0
gridCols    3006 / 1200 / 1189 / 1244 / 1911 twips
            = 150.3 / 60.0 / 59.5 / 62.2 / 95.6 pt
全表 7 行（前 4 行示范 = 2 个班各折成 2 行，后 3 行空行占位）
单元格      vAlign=center；段落无 spacing、无 jc、首列 ind left=640(32pt)
第 2 行     只有 4 个单元格——长姓名「一二三四五六七八」与右侧格合并（对应说明 PDF 第 5 条）
```

要点：第 1 列 150pt ≈ 5.3cm（与说明 PDF 里"把第一列设置宽一点"的 5.30 厘米标注一致）；最后一列 95.6pt 偏宽，是因为示范里放了长姓名（官方用合并单元格解决）。

|---|---|---|---|

| 正文第 1 行 | 175.6 | 122.1 | 首行缩进，缩进 32pt |
| 正文第 2 行 | 206.8 | 90.0 | 行距 31.2 |
| 正文第 3 行 | 238.0 | 90.0 | |
| 特此证明。 | 269.2 | 122.1 | |
| 名单如下: | 362.8 | 122.1 | 其上空两行 |
| 表格第 1 行 | 399.2 | 121.0（班级）/ 239.2（姓名） | 行距 31.2；文字比版心左缘 89.9 偏左 0.9pt，因 tblpX=1779 twips < 左边距 1800 |
| 表格第 2 行 | 430.4 | 239.2 / 331.3 | 长姓名合并了后两格（该行只有 4 个单元格） |
| 日期 | 680.0 | 右缘 **505.4** | 见下方说明 |
| 单位 | 711.2 | 右缘 **505.4** | |

**落款为什么在 680**：全表 7 行 = 4 行内容（2 个班各折成 2 行）+ **3 行空行占位**。浮动表设了 `tblOverlap=never`，表后段落会被推到表底之下：表底 617.6 + 2 个空段 = 679.96 ≈ 680。那 3 行空行是占位用的，说明 PDF 写"行数看具体名单增减"，实际使用时要删——删掉后落款就紧接表格。生成件即按"已删空行"处理。

**落款右缘别量错**：`rawdict` 里该行 bbox 的 x1 是 513.4，但那包含了行末的合成空格字符（16pt 字宽 16pt，汉字「日」的真实右缘是 505.44 = 595.3 − 右边距 89.86）。按**文字**右缘量，官方与生成件都是 505.4，齐平；按 bbox 量会误以为差了 8pt 去追一个不存在的偏差。`verify_pdf.py` 已按文字右缘判定。

生成件与上表逐项对齐：标题 93.7、正文 175.6/206.8/238.0、特此证明 269.2、名单如下 362.8、表格行距 31.2、落款右缘 505.4 全部一致。仅表格首行 y 差 5.2pt——官方用的是浮动表（tblpY=103 twips ≈ 5.15pt），生成件用内联表，不值得为 1.8mm 引入浮动表的排版风险（浮动表在用户改内容时容易串位、压字）。

## 4. 说明 PDF 的 5 条操作要点

第 2–5 页是纯截图（无文字层），下面是从图上读出来的原话：

1. 「插入一个表格（**行数看具体名单增减，五列，一行一般放 4 个名字**）」
2. 「把第一列设置宽一点只用来放班级」——截图里"单元格宽度"填的是 **5.30 厘米**，红字批注：「差不多 5cm 以上，看情况调整，但是要**一行放下来，不能换行**」
3. 「表格第一列文字要与上一段文字对齐」（即与「名单如下：」左对齐）
4. 「如果姓名只有两个字则单独选中，调整宽度」
5. 「如果姓名太长，可以将这一格和后面的格子合并」→「最后选中整个表格设置为无框线」

第 2 条的"不能换行"是整套要求的核心：班级名、每个姓名都必须在各自格内一行放下，这也是 `verify_pdf.py` 用"PDF 行数 vs docx 行数"来兜底的原因。

## 5. 行距为什么是 31.2pt（含表格为什么不跟网格）

16pt 字在 15.6pt 的行网格里占不满一格，Word 会占 2 格 → 2 × 15.6 = 31.2pt。这与"1.5 倍行距"数值巧合相等，但成因不同：把 `docGrid` 删掉再设单倍，行距会掉到 20.8pt。

**表格**是另一套机制，踩过坑：

| 文档 | settings.xml 里的 `w:adjustLineHeightInTable` | compatibilityMode | 表格行距 |
|---|---|---|---|
| 官方《格式示例.docx》 | 无 | 14 | 31.2（靠 trHeight 或换行行高） |
| 学院老 .doc 体系（观众名单） | **有** | 11 | 31.2（表格套网格，行高全 None） |
| 本 skill 生成件（改前） | 无 | 14 | **20.8** ❌ |
| 本 skill 生成件（加标志后） | 有 | 14 | 31.2 ✓ |

单变量实验（同一份 docx，去掉 trHeight 后逐个改动）：

```
原始（无标志，有 cell spacing）        20.8
删 cell 段落 w:spacing                 20.8
删 Normal 样式 w:spacing               23.9
两处都删                                33.9
加 w:adjustLineHeightInTable           31.2  ✓
```

所以 20.8 的病因是**缺兼容标志**，与段落 spacing 无关；`w:spacing` 只影响自然行高。生成件同时用标志 + `trHeight=624 atLeast` 双保险。

## 5.1 学院成品样本实测（2026-11 歌手大赛三件套）

原件在工作区 `_模范样本/`（含真实姓名，不入 skill 资产）。页面/边距/网格与官方模板完全一致：595.3×841.9pt，2.54/3.17cm，`linePitch=312`。

| 项 | 选手名单（1 页） | 嘉宾名单（2 页） | 观众名单（6 页，107 行） |
|---|---|---|---|
| 标题 | 2 行折行，SimSun 22 | 同 | 同 |
| 正文起 | y=200.31 | 188.07 | 200.27 |
| 名单如下 | 356.31 | 375.27 | 356.31 |
| 表格首行 | 387.51（31.2，内嵌） | 406.47（31.2，内嵌） | 408.3（52.0，浮动 `tblpY=416`） |
| 行距 | 31.2 | 31.2 | 31.2（部分行手调 605~641 twips） |
| 第一列 x0 | 122.04 ✓ 与名单如下对齐 | 126.84 ✗ 差 4.8pt | 122.06 ✓ |
| 第一列宽 | 157.9 | ~141.7 | 184.25（`gridCol=3685`，放得下"26汉语言文学1班"） |
| 姓名列宽 | 64.68 | 48（很窄，靠溢出） | 58.95（`1179`），末列 89.75（`1795`） |
| 一行几个名字 | 1~2 | 1~2 | 最多 4 |
| 两字姓名 | `林　霈` `肖　菲`（全角空格撑宽） | `纪　玉` `郭　琦` | `罗　洁` `彭  冰`（两个半角空格） |
| 长姓名 | 排尔扎乃·艾合买提 占 144pt 一行 | 同 | 合并单元格（9 字维语名） |
| 落款 y | 713.55 / 744.75 | 610.11 / 641.31 | 454.12 / 485.32 |
| 落款右缘 | 505.19 | 505.19 | 505.4（bbox 513.4 含行末空格） |
| 表尾 → 落款 | 76.44（2.45 行，疑手误） | 62.4（2 空行） | 62.4（2 空行） |

**结论**

- 稳定项：31.2 行距、右缘 505.4、姓名一行放下、无框线、第一列只放班级。
- 不稳定项：表格浮动与否、`tblW`、列宽、落款空行、`（单位）` 是否删干净（**选手名单忘了删**）。
- `嘉宾名单` 是三份里最糙的（第一列没对齐、姓名连排不分格、列宽 48pt 靠溢出），**不能当范本**。
- 观众名单用浮动表且 `tblpY=416`（20.8pt 偏移），疑为手误；选手/嘉宾都是内嵌表 31.2，与生成件一致。

## 7. 字体可用性

本机已装：`宋体 SimSun`、`仿宋 FangSong`、`黑体 SimHei`、`楷体 KaiTi`、`华文中宋`、`微软雅黑`。
本机**未装**：`方正小标宋_GBK`、`仿宋_GB2312`。

官方 docx 里标题就是宋体、正文就是仿宋，所以默认即达标；若学校另有要求，`--title-font` / `--body-font` 可指定，`--force-canonical-fonts` 可把字体名写死成 方正小标宋_GBK / 仿宋_GB2312（本机没有会回退渲染，PDF 校验会报出实际字体，不会蒙混过关）。
